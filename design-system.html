Design System

The tokens, type scale and component patterns behind Rallo, audited from the live site rather than invented — every value below is what the product actually uses today. Copy the CSS variables at the top of this file to seed a new project, or copy a component's markup straight out of its code panel.

Web-ready as-isComponent markup here is plain HTML + CSS variables — drop it into any HTML, React or Vue project unchanged.
Mobile: values onlyNative apps can't use this markup. Carry over the hex values, type scale and spacing numbers as your starting tokens instead.
Kept honestThis page is not wired to the live site's runtime — when a token changes here, someone still needs to update Rallo.dc.html to match.

Color

Every swatch below is theme-aware — toggle Light/Dark in the header and watch them repaint. Click any swatch to copy its current resolved value.

Primitive → Semantic → Component Components never reference a raw color — they reference a semantic token, which resolves to a different primitive depending on the active theme. That indirection is the entire point: change what a semantic token points to, and every component using it updates, in both themes, without being touched. 
Primitive
  --g-500: #9ECE16                    (light theme, dark theme — same value; lime doesn't invert)

    ↓

Semantic
  --lime: var(--g-500)                (light) → #9ECE16
  --lime: var(--g-500)                (dark)  → #9ECE16   /* unchanged on purpose */
  --ink-on-accent: var(--n-950)       (light) → #0A0A0A
  --ink-on-accent: var(--n-950)       (dark)  → #0A0A0A   /* stays dark — lime never gets light text */

    ↓

Component
  .btn-lime { background: var(--lime); color: var(--ink-on-accent); }
Primitives are internal plumbing, not shown as their own swatch gallery below — a component should never reach past the semantic layer to use one directly.

No shadow scale Rallo doesn't use box-shadow anywhere — separation comes from a 1px border (--border) or a background-color change, never elevation. Motion is a single .18s ease on hover (--ease); the only blur in the whole product is the 14px glass effect on the sticky header (--glass-blur).

Status & Roadmap

Mapped against a full multi-platform design-system spec. The colors/type/spacing above are the tokens Rallo actually has today; this section says which parts of a mature system are real, and which aren't built yet.

Read this before the checkmarks below A design system documents a product. Rallo today is one web surface: a marketing site plus four browsable app screens, no real backend, no dark theme, no data tables, no working auth, no native mobile app. A lot of the requested spec — tables, forms, onboarding flows, mobile-native components, a Figma file tree — has no real surface to be documented from yet. Marking those "done" would mean inventing product decisions that are yours to make, not mine to guess. So: Documented means it's real and covered on this page. Partial means something exists but doesn't meet the full ask. Needs your call means it's buildable right now, without waiting on new product surfaces — the only thing missing is a decision. No surface yet means the underlying screen or flow doesn't exist in the product, so there's nothing to document.
1
BrandPartial

Logo mark + wordmark exist and are documented in Icons ↑. No variations (reverse/mono), no clear-space or minimum-size rule has ever been defined.

1
Color tokensPartial

Ink / Brand / Status / Surface tokens are documented in Colors ↑, but named by role rather than the exact semantic slots this spec asks for. Elevated surface, Divider, Text disabled, Warning, Info and Overlay/scrim don't exist as tokens — because nothing in the product currently needs them (no disabled fields, no elevation, no warning/info status anywhere).

1
Light + Dark themeDocumented

Built on this page — a working toggle in the header, persisted per-visitor, respecting system preference until you choose explicitly. Direction: true black (#0A0A0A), lime unchanged, live/red bumped for contrast. Not yet retrofitted onto Rallo.dc.html itself — see the note below.

Core componentsDocumented

47 components across every category in this spec are now built and documented in Components ↑ — Inputs, Selection, Actions, Navigation, Feedback, Containers, Data, on top of the original 9. AccessibilityPartial

Meaningfully advanced, not finished. Real: a theme-aware focus-visible ring on every interactive element, including ones built as styled <span>s that were retrofitted with tabindex and role rather than left unreachable by keyboard; Checkbox/Radio/Switch/Menu item use real native or fully-semantic elements instead of custom-built widgets; the Tooltip opens on keyboard focus, not just mouse hover; Modal moves focus into itself on open. Not done: no systematic WCAG contrast audit has actually been run against every token pairing, and Combobox's interaction layer stays undone by design (see Selection ↑).

Light & dark theme architectureDocumented

Same primitive layer from #18 gets redefined per theme in one place (a [data-theme] override block plus a prefers-color-scheme fallback) — no component was duplicated. Building this surfaced eight real contrast bugs along the way: places that paired a theme-reactive token with a hardcoded #fff or vice versa (primary button, active segment, "Open"/"Documented" badges, the logo mark). All fixed; see the commit for the specific list.
