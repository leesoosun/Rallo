Design System

The tokens, type scale and component patterns behind Rallo, audited from the live site rather than invented — every value below is what the product actually uses today. Copy the CSS variables at the top of this file to seed a new project, or copy a component's markup straight out of its code panel.

Web-ready as-isComponent markup here is plain HTML + CSS variables — drop it into any HTML, React or Vue project unchanged.
Mobile: values onlyNative apps can't use this markup. Carry over the hex values, type scale and spacing numbers as your starting tokens instead.
Kept honestThis page is not wired to the live site's runtime — when a token changes here, someone still needs to update Rallo.dc.html to match.

Color

Every swatch below is theme-aware — toggle Light/Dark in the header and watch them repaint. Click any swatch to copy its current resolved value.

Primitive → Semantic → Component Components never reference a raw color — they reference a semantic token, which resolves to a different primitive depending on the active theme. That indirection is the entire point: change what a semantic token points to, and every component using it updates, in both themes, without being touched. 
Primitive
  --g-500: #9ECE16                    (light theme, dark theme — same value; lime doesn't invert)

    ↓

Semantic
  --lime: var(--g-500)                (light) → #9ECE16
  --lime: var(--g-500)                (dark)  → #9ECE16   /* unchanged on purpose */
  --ink-on-accent: var(--n-950)       (light) → #0A0A0A
  --ink-on-accent: var(--n-950)       (dark)  → #0A0A0A   /* stays dark — lime never gets light text */

    ↓

Component
  .btn-lime { background: var(--lime); color: var(--ink-on-accent); }
Primitives are internal plumbing, not shown as their own swatch gallery below — a component should never reach past the semantic layer to use one directly.

No shadow scale Rallo doesn't use box-shadow anywhere — separation comes from a 1px border (--border) or a background-color change, never elevation. Motion is a single .18s ease on hover (--ease); the only blur in the whole product is the 14px glass effect on the sticky header (--glass-blur).

Status & Roadmap

Mapped against a full multi-platform design-system spec. The colors/type/spacing above are the tokens Rallo actually has today; this section says which parts of a mature system are real, and which aren't built yet.

Read this before the checkmarks below A design system documents a product. Rallo today is one web surface: a marketing site plus four browsable app screens, no real backend, no dark theme, no data tables, no working auth, no native mobile app. A lot of the requested spec — tables, forms, onboarding flows, mobile-native components, a Figma file tree — has no real surface to be documented from yet. Marking those "done" would mean inventing product decisions that are yours to make, not mine to guess. So: Documented means it's real and covered on this page. Partial means something exists but doesn't meet the full ask. Needs your call means it's buildable right now, without waiting on new product surfaces — the only thing missing is a decision. No surface yet means the underlying screen or flow doesn't exist in the product, so there's nothing to document.
1
BrandPartial

Logo mark + wordmark exist and are documented in Icons ↑. No variations (reverse/mono), no clear-space or minimum-size rule has ever been defined.

1
Color tokensPartial

Ink / Brand / Status / Surface tokens are documented in Colors ↑, but named by role rather than the exact semantic slots this spec asks for. Elevated surface, Divider, Text disabled, Warning, Info and Overlay/scrim don't exist as tokens — because nothing in the product currently needs them (no disabled fields, no elevation, no warning/info status anywhere).

1
Light + Dark themeDocumented

Built on this page — a working toggle in the header, persisted per-visitor, respecting system preference until you choose explicitly. Direction: true black (#0A0A0A), lime unchanged, live/red bumped for contrast. Not yet retrofitted onto Rallo.dc.html itself — see the note below.

2
TypographyDocumented

Family, weights and scale are covered in Typography ↑. Sizes use clamp() to interpolate rather than fixed desktop/tablet/mobile numbers — can be broken into explicit tiers if you want the exact ladder this spec describes.

3
SpacingDocumented

Scale is covered in Spacing ↑. No separate page/section/grid-gap token distinct from the general scale yet; the 1280px container width isn't tokenized.

4
Layout & grid — WebsitePartial

Max-width and gutters are used consistently in practice, not formalized as a grid token.

4
Layout & grid — Web AppNo surface yet

No sidebar / app-shell / dashboard / table layout exists — the "web app" screens are the same page pattern as the marketing site.

4
Layout & grid — MobileNo surface yet

No native mobile app exists in this repo.

5
Responsive systemPartial

Breakpoints are used ad hoc (clamp(), one 760px query on this page) rather than tokenized. The specific transformations asked for — table→card, sidebar→drawer, modal→sheet — don't apply because none of those components exist yet.

6
Elevation & surfacesDocumented

Covered in Spacing ↑ as a deliberate absence — Rallo uses borders, not shadows, at any elevation. Dark-theme elevation now has an answer too: --surface-dark raises a step (#0A0A0A → #1C1C19) rather than trying to go darker than the page itself — see the CTA banner in Components ↑ with Dark mode on.

7
Borders & radiusPartial

Widths and the radius scale are documented in Spacing ↑. Gap: no visible focus ring exists anywhere in the product — a real, fixable accessibility issue, not a missing surface.

8
IconsPartial

Documented honestly in Icons ↑ — there is no icon library, only the logo mark and a handful of text glyphs. A real icon set (sizes, stroke width, filled/outline variants) is new production work, not documentation of something that exists.

9
Core componentsPartial

9 of the ~80 components this spec lists exist and are documented in Components ↑: Button, Badge, Segmented control, Tabs, Card, List row, Chip, Empty state, CTA banner. Nearly everything else — every text input, most selection controls, icon buttons, alerts/toasts/tooltips/skeletons, modals/drawers/popovers/dropdowns, tables, avatars — has no surface in the product yet.

10
Component statesNeeds your call

Every component that exists today effectively only has Default and Hover. No Focus, Disabled, Loading or Error state is defined anywhere — buildable right now, on existing components, without waiting on new product surfaces.

11
Complex product patternsNo surface yet

Search / filter / sort are real and documented in Components ↑ (the tournaments listing). Login / signup is a placeholder modal with no actual input fields. Onboarding, account setup, CRUD, delete flows, notifications, settings, profile, dashboard — none exist; the product has no backend.

12
Tables & data-dense UINo surface yet

Zero tables anywhere in the product.

13
FormsNo surface yet

No real form exists — the auth modal has no input fields to define rules for.

14
Navigation architecturePartial

Website nav is real and documented in Components ↑ (the sticky navbar). Web-app nav (sidebar, user menu) and mobile nav have no surface yet.

15
Mobile-specific componentsNo surface yet

No native mobile app exists in this repo.

16
AccessibilityNeeds your call

The most important buildable-now item on this list. Nothing has been contrast-checked, there are no visible focus states, and there's no screen-reader pass — except the hero animation, which does correctly respect prefers-reduced-motion. Worth doing regardless of what else gets built.

17
MotionPartial

One duration exists (.18s ease) and is documented in Spacing ↑, plus reduced-motion handling on the hero. No Normal/Slow tiers or modal/drawer/dropdown animation, since those components don't exist yet.

18
Design tokens (Primitive → Semantic → Component)Documented

Built — see the worked example at the top of Colors ↑. Semantic token names stayed the same (--ink, --lime, etc.) so every existing copyable snippet on this page kept working; primitives (--n-*, --g-*, --r-*) sit underneath as the layer semantics actually reference.

19
Light & dark theme architectureDocumented

Same primitive layer from #18 gets redefined per theme in one place (a [data-theme] override block plus a prefers-color-scheme fallback) — no component was duplicated. Building this surfaced eight real contrast bugs along the way: places that paired a theme-reactive token with a hardcoded #fff or vice versa (primary button, active segment, "Open"/"Documented" badges, the logo mark). All fixed; see the commit for the specific list.

20
Figma architectureN/A

This project isn't authored in Figma. The equivalent structure is this repo's file layout — Rallo.dc.html plus design-system.html — not a Figma page tree.

21
DocumentationPartial

Every component in Components ↑ has a live preview and copyable code, but not the fuller format this spec wants — when to use / when not to use, content guidelines, do/don't examples. Addable incrementally per component.

22
Developer handoffPartial

Token naming (kebab-case CSS custom properties) and component class naming exist as a convention in practice but aren't written down as a rule. No versioning or changelog for this page yet.

23
QA / definition of doneNot started

This is a checklist to run against a finished system, not something to build. Worth revisiting once the gaps above close.

Recommended next step

Tokens and theming (#1, #18, #19) are done on this page. Two things remain buildable right now without waiting on new product surfaces: Component states (#10 — Focus, Disabled, Loading, Error are undefined even on components that already exist) and Accessibility (#16 — no contrast audit has run, and there's still no visible focus ring anywhere). Everything else stays "no surface yet" until that surface is actually being built, so this page keeps documenting the real product rather than a fictional one. Separately: this theme architecture has not been retrofitted onto Rallo.dc.html — that's a larger, separate pass across the live site's ~1400 lines, worth doing deliberately rather than folded into this one.

Source of truth: Rallo.dc.html · this page is audited against it, not the other way around — if they disagree, the live site is right.
